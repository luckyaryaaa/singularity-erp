# v0.49.0 — Canonical Warehouse Terminal Grain-Flip (ledger write grain)

**Tanggal:** 29 Juli 2026
**Migration:** `084_warehouse_terminal_grain_flip.sql`
**Pola cutover:** introduce → dual-write → reconcile → read-switch → **grain-flip**

## Konteks

Stage 1 (076) memperkenalkan `org_warehouse_id`; Stage 2A (082) menjadikannya
NOT NULL + trigger-guarded pada seluruh ledger; Stage 2B (083) menambahkan
read-switch reversibel yang membuktikan grain kanonik value-preserving. Stage
terminal ini memindahkan grain OTORITATIF **tulis** saldo persediaan ke gudang
kanonik.

## Yang berubah

| Aspek | Sebelum | Sesudah |
|---|---|---|
| Keunikan `inventory_balances` | `(product, warehouse_id)` cabang | + `(product, org_warehouse_id)` kanonik (keduanya, 1:1) |
| `posting.applyBalance` | key saldo per cabang | key saldo per gudang kanonik (cabang → gudang default) |
| `stock-reservations.syncBalance` | `ON CONFLICT(product, warehouse_id)` | `ON CONFLICT(product, org_warehouse_id)` |
| Advisory lock | per cabang | tetap per cabang (selaras syncBalance) |

**Value-preserving.** Karena tiap cabang masih 1:1 dengan gudang defaultnya
(080/082), keying kanonik menemukan/menyimpan baris yang sama dan angka tidak
berubah. Seluruh regresi posting (GR/issue/transfer/opname/produksi/delivery)
tetap hijau.

**Kompatibilitas dipertahankan.** Keunikan cabang `(product, warehouse_id)`
sengaja TIDAK dilepas: masih dipakai oleh opening-inventory dan sejumlah setup
sebagai `ON CONFLICT`, dan menjaga invariant 1:1. Read-site yang memfilter per
cabang tetap benar (`org_warehouse.branch_id = warehouse_id`).
