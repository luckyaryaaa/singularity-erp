# v0.40.0 — Warehouse Execution Task Engine (WMS minimal task flow)

**Tanggal:** 29 Juli 2026
**Cakupan blueprint:** §9.8 Inventory and Warehouse (bagian task flow)
**Migration:** 075 `warehouse_task_engine`

## 1. Tujuan

Menjadikan eksekusi gudang — receiving, put-away, pick, pack, ship, dan cycle
count — sebagai **tugas bertipe** yang dapat ditugaskan, diklaim, dikerjakan, dan
diaudit, bukan mutasi stok yang terjadi diam-diam. Ini menutup bagian task flow
dari P1 Warehouse pada audit 28 Juli 2026.

Engine berdiri **di atas** model lot/bin yang sudah ada (migrasi 058). Ledger
stok tidak diubah: migrasi Branch-as-Warehouse kanonik (memindahkan `stock_lots`
dari `branches` ke `org_warehouses`) tetap pekerjaan tersendiri dan sengaja tidak
dicakup di sini.

## 2. Model data (`warehouse_tasks`)

| Aspek | Keputusan |
|---|---|
| Tipe tugas | `RECEIVE`, `PUTAWAY`, `PICK`, `PACK`, `SHIP`, `COUNT` |
| Siklus hidup | `OPEN` → `CLAIMED` → `IN_PROGRESS` → `DONE` / `CANCELLED` |
| Prioritas | `LOW`, `NORMAL`, `HIGH`, `URGENT` |
| Cakupan | `branch_id` (= gudang pada model saat ini), RLS `app_branch_visible` |
| Concurrency | kolom `version` optimistic lock pada setiap transisi |
| Integritas | constraint DB: put-away wajib lot + rak tujuan; pick wajib lot; tugas tertutup wajib jejak penyelesaian/pembatalan |
| Tautan | `source_module` + `source_document_id` (GR/SO/WO/opname) |
| Audit | `runtime.audit` old/new/reason pada create dan setiap transisi |

Indeks: papan kerja `(branch_id, status, priority, due_at)`, "tugas saya"
`(assigned_to, status)` untuk status berjalan, dan telusur balik dokumen sumber.

## 3. Perilaku kunci

- **Put-away menyelesaikan diri secara nyata.** `POST .../complete` untuk tugas
  `PUTAWAY` memanggil penempatan lot yang sudah ada (`bin-execution.putaway`):
  lot dikunci, cabang & rak divalidasi, gerakan lot dicatat, dan diaudit. Status
  `DONE` berarti stok benar-benar berpindah — tidak ada jalur mutasi stok kedua.
- **Notifikasi ≠ penyelesaian.** Menutup tugas menuntut transisi eksplisit
  dengan `version`, bukan sekadar membaca antrean.
- **Isolasi cabang berlapis.** Permission (`assertBranchScope`) di aplikasi dan
  RLS `warehouse_tasks` di database.

## 4. Endpoint (router Inventory, +6 handler → 20)

| Method | Path | Guard |
|---|---|---|
| GET | `/api/inventory/tasks` | delegated `inventory.view` |
| POST | `/api/inventory/tasks` | delegated `inventory.edit` + idempotency |
| POST | `/api/inventory/tasks/{id}/claim` | delegated `inventory.edit` + version |
| POST | `/api/inventory/tasks/{id}/start` | delegated `inventory.edit` + version |
| POST | `/api/inventory/tasks/{id}/complete` | delegated `inventory.edit` + version + idempotency |
| POST | `/api/inventory/tasks/{id}/cancel` | delegated `inventory.edit` + version + reason |

Authorization matrix: Inventory 14→20 handler, seluruh handler baru delegated dan
terklasifikasi (`directGuards + delegated + public === handlers`); total baseline
naik ke **297 handler**. OpenAPI mengekspos enam operasi ber-`cookieAuth`.

## 5. Frontend

Tab **Tugas gudang** pada modul Persediaan: ringkasan terbuka/berjalan/lewat
tempo/selesai, tabel tugas dengan prioritas dan jatuh tempo (highlight lewat
tempo), aksi klaim/mulai/selesai/batal ber-optimistic-lock, dan dialog pembuatan
tugas (dengan pemilih lot & rak untuk put-away).

| Gate | Hasil |

| Syntax | repo, route, dan modul frontend lulus `node --check` |

Test `test/wave18-warehouse-tasks.test.js` mencakup: siklus hidup penuh dengan
efek put-away nyata, optimistic lock (versi salah ditolak), status guard
(selesai/mulai sebelum klaim ditolak), penolakan lot/rak lintas cabang, constraint
put-away tanpa rak tujuan, pembatalan wajib beralasan, isolasi papan kerja lintas
cabang, dan liveness skema (kode + migrasi benar-benar merujuk tabel).
