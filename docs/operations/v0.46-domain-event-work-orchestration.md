# v0.46.0 — Domain Event → Work Orchestration

**Tanggal:** 2026-07-29  
**Cakupan blueprint:** §4.4 Unified Work Item, §4.5 Domain Events, Tahap B
Work Orchestration Integration  
**Migration:** `081_domain_event_work_item_projection.sql`

## Hasil

Kejadian domain yang membutuhkan keputusan atau tindakan manusia tidak lagi
berhenti sebagai notifikasi informasional. Event `action-required` ditulis ke
transactional outbox pada transaksi bisnis yang sama, kemudian diproyeksikan
secara idempoten menjadi Unified Work Item dan notifikasi `ACTION_REQUIRED`.
Saat sumber selesai, event `action-resolved` menutup Work Item otomatis dengan
audit trail.

Sumber awal yang sudah terhubung:

- approval dokumen per tahap/level;
- assignment dan penyelesaian Warehouse Task;
- NCR/QC yang melahirkan CAPA;
- exception atau `NOT_RUN` pada reconciliation evidence;
- invoice overdue, dunning, dan credit hold.

## Kontrak dan kontrol

- Event ber-versi: `work.action-required.v1` dan
  `work.action-resolved.v1`.
- `automation_key` mencegah satu kejadian bisnis membuat Work Item ganda.
- `source_event_id` mencegah replay event yang sama membuat duplikat.
- Outbox mempunyai status `PENDING/PUBLISHED/DEAD_LETTER`,
  exponential backoff, maksimum attempt terkonfigurasi, error terakhir, dan
  timestamp dead-letter.
- Proyeksi berjalan sebagai system transaction dengan RLS context eksplisit.
- Audit mencatat `PROJECT`, `AUTO_COMPLETE`, `OUTBOX_DEAD_LETTER`, dan
  `OUTBOX_RETRY`.
- Dead-letter dapat dilihat tanpa mengekspos payload melalui
  `GET /api/governance/outbox`.
- Retry hanya untuk `DEAD_LETTER`, membutuhkan `settings.edit`, recent MFA,
  alasan minimal 10 karakter, dan audit melalui
  `POST /api/governance/outbox/{id}/retry`.
- Notifikasi action-required mengikuti target pengguna atau role dan dedupe key
  Work Item.

## Operasi

Konfigurasi:

```dotenv
OUTBOX_MAX_ATTEMPTS=5
```

Nilai valid 1–20; default aman 5. Backoff dimulai 5 detik dan dibatasi maksimum
300 detik. Operator tidak boleh mengubah payload event langsung. Perbaiki akar
masalah kontrak/sumber, lalu gunakan endpoint retry dengan alasan yang dapat
diaudit.
