# v0.47.0 — Canonical Warehouse Stage 2A + WMS Mobility

**Tanggal:** 29 Juli 2026  
**Migration:** `082_warehouse_stage2a_mobility.sql`  
**Pola cutover:** introduce → dual-write guard → reconcile → read-switch

## Outcome

Stage 2A menutup gap eksekusi fisik prioritas tertinggi tanpa big-bang terhadap
ledger lama. Semua record stok utama kini memiliki `org_warehouse_id` yang
tervalidasi berada di cabang yang sama. Bin otomatis menentukan storage
location dan gudang kanonik.

Objek WMS baru:

- handling unit/license plate dan komposisi lot;
- lifecycle OPEN → SEALED → STAGED → LOADED → SHIPPED;
- scan session per Warehouse Task;
- langkah scan LOT/BIN/HU yang berurutan;
- evidence scan append-only;
- health view rekonsiliasi dimensi;
- canonical location ledger sampai grain bin dan expiry date.

Warehouse Task dengan `scanRequired=true` gagal tertutup: status DONE ditolak
sampai sesi scan berstatus COMPLETED. Wrong-order scan, entity yang tidak cocok,
operator lain, versi stale, dan gudang lintas cabang ditolak.

## Security dan correctness

- RLS `branch_scope` pada handling unit, item, scan session, dan scan event.
- Trigger database mengunci scope branch/warehouse/location/bin.
- Scan event tidak dapat diubah atau dihapus.
- Quantity handling unit tidak dapat melebihi saldo lot aktif.
- Semua lifecycle memakai optimistic version dan audit trail.
- Create handling unit serta start scan session memakai `Idempotency-Key`.

## Batas Stage 2A

`warehouse_id` ber-grain branch belum dihapus karena masih menjadi compatibility
scope pada modul lama. Cutover Stage 2B baru boleh dilakukan setelah health
reconciliation konsisten nol, negative concurrency test Stage 2B lulus, dan
rollback/read-switch rehearsal tervalidasi.
