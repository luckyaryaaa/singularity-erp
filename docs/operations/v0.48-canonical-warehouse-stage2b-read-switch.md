# v0.48.0 — Canonical Warehouse Stage 2B: Reconcile + Read-Switch

**Tanggal:** 29 Juli 2026
**Migration:** `083_warehouse_stage2b_read_switch.sql`
**Pola cutover:** introduce → dual-write guard → **reconcile → read-switch**

## Konteks

Stage 2A (082) menyelesaikan INTRODUCE + DUAL-WRITE GUARD: setiap ledger stok
(`inventory_balances`, `inventory_movements`, `stock_reservations`, `stock_lots`,
`warehouse_tasks`) membawa `org_warehouse_id` NOT NULL yang tervalidasi berada di
cabangnya, dijaga trigger. Stage 2B menambahkan fase RECONCILE + READ-SWITCH
secara **reversibel**, tanpa membalik kunci scope/RLS.

## Yang ditambahkan

| Objek | Fungsi |
|---|---|
| View `warehouse_read_switch_reconciliation` | Per produk×cabang: total qty/value pada grain cabang (`warehouse_id`) vs grain `org_warehouse` (dipetakan balik ke cabang). Selisih wajib nol. |
| View `warehouse_read_switch_health` | Ringkasan gate: `balance_grain_mismatch` + `dimension_issues`. Nol = aman switch. |
| Setting `warehouse.read_grain` | `BRANCH` (default) atau `CANONICAL`, di `system_settings`. |
| `listInventory` grain-aware | Default BRANCH (perilaku identik); CANONICAL menampilkan gudang kanonik. |
| Endpoint | `GET /api/inventory/reconciliation`, `GET /api/inventory/stock-by-warehouse`, `POST /api/inventory/read-grain`. |

## Perilaku kunci

- **Value-preserving.** Read-switch tidak mengubah angka, hanya grain: qty pada
  grain kanonik = qty pada grain cabang (dibuktikan test + view rekonsiliasi).
  Selama tiap saldo hanya memetakan ke satu gudang default dalam cabangnya
  (dijamin 082), selisih selalu nol.
- **Reversibel + ber-gate.** Beralih ke CANONICAL ditolak bila rekonsiliasi belum
  bersih; kembali ke BRANCH **selalu** boleh (rollback/rehearsal). Flag dijaga
  `settings.edit` dan setiap perubahan diaudit old/new.
- **Kompatibilitas dijaga.** `warehouse_id` ber-grain cabang tetap kunci scope/RLS;
  Stage 2B tidak menyentuh ~197 titik itu.
