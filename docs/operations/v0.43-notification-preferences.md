# v0.43.0 — Notification Preferences

**Tanggal:** 29 Juli 2026
**Cakupan blueprint:** §5.2 Workspace critical updates (#6/#7), audit Workspace 6.7
**Migration:** 078 `notification_preferences`

## 1. Tujuan

Notifikasi sudah per-recipient dengan read receipt per pengguna
(`notification_receipts`), tetapi pengguna belum bisa MEMILIH kategori mana yang
ingin diterima. Wave ini menutup ⬜ audit Workspace 6.7 "Notification Preferences
Are Missing".

## 2. Model & keputusan

| Aspek | Keputusan |
|---|---|
| Tabel | `notification_preferences` (PK `user_id` + `category`) |
| Kategori | ACTION_REQUIRED, WARNING, INFORMATION, SUCCESS, SYSTEM_ALERT |
| Kontrol | `muted` (sembunyikan in-app) + `email_enabled` (per kategori) |
| Titik filter | **jalur baca** (`listNotifications` + `unreadCount`), bukan jalur tulis |
| SYSTEM_ALERT | tidak dapat di-mute (dijaga repo) |
| Isolasi | RLS `own_user` (per pengguna; bypass `app.is_system` untuk worker/test) |

**Mengapa filter di jalur baca, bukan tulis:** notifikasi bisa bertarget pengguna
ATAU peran (`target_role`). Menyaring saat baca menangani keduanya secara seragam,
dan notifikasi tidak pernah hilang dari basis data — hanya tak ditampilkan bagi
pengguna yang me-mute kategorinya. Ini juga membuat perubahan bersifat aditif
tanpa menyentuh belasan titik pemanggil `operations.notify`.

## 3. Endpoint & UI

- `GET /api/notifications/preferences` — preferensi kelima kategori (default:
  tampil in-app, email mati).
- `POST /api/notifications/preferences` — set satu kategori (upsert, audit
  old/new). Guard `notification.view`. Router Operations 12→14 handler; total
  baseline authorization matrix **304 handler**.
- Panel preferensi di UI notifikasi: toggle mute + email per kategori.

## 5. Catatan terkait (temuan outbox)

Rencana awal wave ini adalah proyeksi domain-event → work item (§4.5). Investigasi
menemukan outbox saat ini hanya meng-emit **empat event informasional**
(invoice/payment/PO/quotation `.updated/.posted`) — tak ada yang "butuh
tindakan". Memproyeksikan itu ke work item akan menghasilkan noise. Karena itu
proyeksi ditunda sampai emisi event action-required diperluas lintas modul
(approval, quality-failed, credit-hold, reconciliation-exception), dan wave ini
dialihkan ke Notification Preferences yang tertutup dan bernilai jelas.

## 6. Gate manusia (tidak berubah)

UAT 13 role, security retest manual, persetujuan enam rekonsiliasi, training, DR
RTO/RPO, offsite proof, dan Owner sign-off tetap fail-closed. Status v0.43.0
adalah engineering release candidate, bukan izin aktivasi produksi.
