# v0.45 — Fresh-Database Warehouse Invariant

## Masalah yang ditemukan

Migration 076 hanya membuat gudang default untuk cabang yang sudah ada ketika
migration dijalankan. Pada database fresh, seed membuat cabang setelah seluruh
migration selesai sehingga cabang aktif dapat tidak mempunyai gudang default.
Development database lama tetap hijau karena cabangnya sudah dibackfill.

## Perbaikan

Migration 080 menambahkan trigger lifecycle pada `branches`. Setiap cabang aktif
baru atau yang diaktifkan kembali:

1. memakai default aktif yang sudah ada;
2. mempromosikan satu warehouse existing bila belum ada default; atau
3. membuat warehouse default baru dengan kode unik.

Fungsi trigger berjalan `SECURITY DEFINER` dengan `search_path` terkunci.
Migration juga memperbaiki cabang aktif yang telanjur tidak mempunyai default.
